# 账号入口、登录拦截与个人资料设计

## 目标

补齐账号体系在主界面中的可发现性和闭环体验：访客能看到登录入口；未登录发送消息时被明确提示并跳转登录；登录用户在侧边栏底部看到头像菜单，可退出登录或进入个人资料页修改自己的显示名称和头像。

## 交互设计

### 侧边栏账号区

- 固定在侧边栏底部，位于设置和主题按钮上方，视觉位置参考用户截图。
- 账号功能关闭时不显示，保持原有访问码模式界面不变。
- 账号功能开启但未登录时，显示头像轮廓、“登录 / 注册”文案和可点击区域。
- 已登录时显示头像、显示名称（无显示名称时使用用户名）和角色；窄侧栏仅显示头像。
- 点击已登录账号区打开菜单：个人资料、管理后台（仅管理员）、退出登录。
- 点击区域外或按 Escape 关闭菜单；移动端菜单采用贴近底部的弹层样式。

### 未登录发送拦截

- 用户仍可浏览首页、助理和历史界面。
- 在消息真正写入会话和请求模型之前检查账号状态。
- 账号功能开启且没有有效用户时，不创建用户消息、不调用模型接口。
- 弹出确认提示“登录后才能开始对话”，主操作跳转登录页，取消则留在当前页面。
- 跳转时保存当前 hash 路由；登录成功后优先返回原页面，否则进入聊天页。
- 服务端现有会话鉴权继续保留，前端拦截只改善体验，不替代安全边界。

### 个人资料页

- 新增 `/profile` 路由，只允许已登录用户访问；匿名用户跳转登录页。
- 展示只读用户名和角色，可修改显示名称与头像 URL。
- 头像 URL 为空或加载失败时显示用户名首字符生成的默认头像。
- 保存成功后刷新统一账号状态，侧边栏立即同步；失败时保留输入并显示错误。
- 本页不能修改角色、禁用状态、密码或其他用户资料。

## 架构与数据流

- 新增客户端 `AccountProvider`，集中请求 `/api/account/session`，暴露 `enabled`、`user`、`loading`、`refresh` 和 `logout`。
- `Home` 在路由树外层提供账号上下文；侧边栏、聊天发送逻辑、登录页和个人资料页共享同一状态。
- 新增 `/api/account/profile`：GET 返回当前用户，PATCH 仅接受 `displayName` 和 `avatar`。
- 领域服务新增本人资料更新方法，明确禁止通过自助接口修改角色或状态，并写入审计记录。
- 登录页读取 `returnTo`，成功后刷新账号上下文并返回原路由。

## 错误处理与边界

- 账号功能关闭：不拦截聊天、不显示账号入口、不影响原访问码逻辑。
- 会话过期：发送时重新确认会话并按匿名流程提示登录。
- 退出登录：清理服务端会话、刷新上下文、关闭菜单并保留当前可浏览页面。
- 非法头像值或过长显示名称由领域服务拒绝，API 返回结构化错误。
- `returnTo` 只接受站内 hash 路由，防止开放重定向。

## 测试与验收

- 领域测试：本人可修改显示名称/头像，不能修改角色；非法资料被拒绝。
- API/辅助函数测试：安全解析 returnTo、账号功能关闭不拦截、匿名发送需要登录。
- UI 辅助测试：头像回退、显示名称和菜单项计算。
- HTTP 联调：匿名 session、登录、GET/PATCH profile、退出后 session 失效。
- TypeScript、专项 Jest、`git diff --check`、生产构建全部通过。
- 人工核验：侧边栏底部入口、菜单定位、登录返回、个人资料保存、移动端布局。

## 不在本次范围

- 本地头像文件上传、裁剪或对象存储。
- 修改用户名、密码和账号角色。
- 未登录时强制阻止浏览整个应用。
