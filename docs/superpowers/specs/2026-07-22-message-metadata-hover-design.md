# 消息助手信息与悬停操作设计

## 目标

让助手消息始终显示真实的助手名称，并把时间、模型和操作按钮收纳到同一条信息行中：桌面端悬停消息时显示，移动端始终显示。

## 范围

- 仅调整对话消息展示，不改变消息数据结构、发送逻辑和操作行为。
- 助手名称优先使用精选助手名称，否则使用当前会话的 `session.mask.name`，为空时显示默认助理文案。
- 模型名称继续读取消息实际使用的 `message.model`，为空时回退到会话当前模型。
- 时间继续读取 `message.date`，上下文消息继续显示既有的上下文提示。

## 桌面端布局

- 助手消息头部固定显示头像和助手名称。
- 时间和模型组成次要元信息，默认不可见，不占用突兀的视觉空间。
- 鼠标进入整条助手消息后，元信息淡入；操作按钮显示在消息正文下方，贴近 LobeHub 的气泡操作栏。
- 信息行采用单行弹性布局，空间不足时允许元信息收缩；操作栏独立占据正文下方一行。
- 助手正文保持现有内容宽度、排版和代码块样式。

## 移动端布局

- 助手名称、时间、模型和操作按钮始终可见，不依赖悬停。
- 信息行允许换行，避免操作按钮把正文区域撑宽。
- 用户消息沿用现有右侧气泡布局，日期显示在气泡上方，操作栏显示在气泡下方。

## 交互与无障碍

- 原有重试、删除、置顶、复制、朗读和停止操作保持不变。
- 键盘聚焦到操作按钮时，即使没有鼠标悬停，信息区也应显示。
- 淡入只改变透明度与可交互状态，不使用位移动画，避免视觉抖动。

## 验证

- 类型检查与 ESLint 通过。
- 桌面端验证默认状态和消息悬停状态。
- 窄屏验证元信息与操作按钮始终显示且不横向溢出。
- 验证精选助手、普通助手、消息模型为空和上下文消息四种情况。
